# Шпаргалка к собеседованию: «Сосны»

**Почему Astro, а не React-SPA?**
Контентный сайт: важны первая загрузка и SEO. Astro выдаёт готовый HTML и не
шлёт JS по умолчанию; интерактив подключается модулями точечно, тяжёлые —
лениво. 270 страниц квартир — статические файлы через `getStaticPaths`.

**Как сделан 3D-квартал без моделей?**
three.js: башни — `BoxGeometry` с canvas-текстурой фасада, горящие окна —
`emissiveMap`, 400 сосен — `InstancedMesh` (один draw call), выбор башни —
`Raycaster`. three.js грузится лениво, кадры — только когда блок на экране.

**Почему `replaceState` для фильтров?**
Ползунок меняет адрес десятки раз — `pushState` засорил бы историю, и «Назад»
стал бы бесполезным. При этом ссылкой на подборку можно поделиться.

**Как одна карточка работает и при сборке, и в браузере?**
Функция возвращает HTML-строку: Astro вставляет через `set:html`, модуль
каталога — через `innerHTML`. Данные только свои — XSS нет.

**Зачем генератор с зерном?**
Демо-данные должны быть одинаковыми при каждой сборке: иначе цены и статусы
менялись бы, а ссылки на квартиры вели бы на другие квартиры.

**Формула ипотеки?**
Аннуитет: `S · r(1+r)ⁿ / ((1+r)ⁿ − 1)`; при ставке 0 — `S / n` (иначе деление
на ноль).

**Как экономится трафик на планировках?**
Четыре SVG-файла на типы квартир генерируются при сборке и кешируются браузером
на все карточки; на странице квартиры SVG встраивается с её площадью.

**Что бы улучшил?**
Данные из CRM (JSON при сборке или инкрементальная пересборка), фото и
3D-туры квартир, сравнение квартир, e2e-тесты фильтров.
